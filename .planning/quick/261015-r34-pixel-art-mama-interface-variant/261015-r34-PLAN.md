- Execution mapping: Tasks 1–3.

## High-level design and rationale

The manifest adds `ui.typography.profile: "pixel"` and independent `ui.chrome: "pixel"`. Default `ui.chrome: "classic"` preserves current styling. The browser binds these to `data-type-profile` and `data-chrome`; selecting one never selects the other. Pixel mode is application-owned CSS, not authored CSS/selectors or a generic style catalog.

Preserve the existing `dm-sans` snapshot's singular `font` URL. For `pixel`, the server alone supplies `ui.typography.fonts: { jersey10, silkscreen }` URLs from two fixed files. Browser font families, descriptors and URL allowlists are fixed in code. Manifests still accept only profile and scale, never `font`, `fonts`, family names or paths. Keep existing scale range 0.9–1.1. No new shared script or font registry is required for these fixed profiles.

New private `mama-pixel` independently extends `starnet`, like Mama. Its scene and crew declarations and image bytes match Mama exactly. At 980K for the entire old pack, regular-file copying is simpler and safer than a new cross-pack ownership protocol, symlinks or hardlinks. Original Mama's 231-file digest inventory stays identical. Only consumed art is copied; new logo/fonts replace old UI resources inside the variant.

Risks and safeguards: larger pixel metrics can overflow dense panels; check real 390px and desktop layouts. Decorative clipping can hide focus or popovers; clip pseudo-elements only. Font headers cannot prove decoding; validate both synthetic structure and real browser usability. Font failure must not affect observed source health. All screenshot evidence stays private, with presentation fixtures where possible.
