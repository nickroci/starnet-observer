# Observer Theme Foundation and Local Comparison Implementation Plan

**Goal:** Preserve the existing default and deliver two real-app Mama comparison packs: `mama-classic` (B), the existing isometric sci-fi station maximally styled toward Mama, and `mama` (C), a complete warm isometric home-office with original human crew.

**Architecture:** Config remains the selection authority. A startup loader reads bounded installed JSON, validates and resolves it against the exact bundled default, then the existing nonce bootstrap delivers one immutable appearance snapshot. CSS, fixed station/home-office paint strategies and sprite runtime consume that snapshot. Office surfaces, furniture, crew and logo are original local PNGs; the application owns fixed tiling/anchors and depth composition. Observation, identity, layout, geometry and routing remain application-owned.

**Tech stack:** Node.js 22.13+ built-ins, plain browser JavaScript/CSS, JSON, PNG and local WOFF2; existing Node assert/VM/recording-context tests; real browser verification. No npm dependencies.

## Shared contracts

Config extends existing `theme` with `pack`: lowercase ID matching `^[a-z0-9][a-z0-9-]{0,31}$`; omitted selects `starnet`. Existing `fx` and `colors` validation stays unchanged. Absent selected pack fails startup, like other invalid config. No `setPreferred` or browser pack persistence exists in this version. Edit config, restart server, reload page. FX behavior stays under existing owner.

Local installation itself registers a pack: validated `theme.pack` ID resolves only to fixed `frontend/assets/themes/<id>/theme.json`. Default `starnet` is tracked; local ignored directories `mama-classic` and `mama` remain selectable through ignored config presets. No catalog or second configuration store is needed. An absent selected manifest fails startup with an unknown/uninstalled-pack error; an existing malformed selected pack degrades to default with a warning. Default installation failure fails startup. Default pack has `version:1`, `id:"starnet"`; custom manifests have `version:1`, their selected `id`, and `extends:"starnet"`. No inheritance chain. Author validation discovers immediate non-symlink pack directories under the fixed root (at most 16, validates names), then reuses the same loader/schema; a default-only clean checkout succeeds. Runtime loads only selected pack/default, never all directories.

Pack fields are `version`, `id`, `extends` (custom only), `ui`, `scene`, `crew`. `ui` permits only `colors`, `typography`, `shapes`, `decor`, `logo`; `scene` permits only `colors`, `projectAccents`, `art`, `backgroundFx`, `ambientFx`. `ui.colors` and `scene.colors` are flat semantic key/color maps; `scene.projectAccents` is ten ordered colors retaining the current floor names/slot identity. Home-office displays these accents only as rug/trim/stripe or small furnishing accents, never luminous industrial floor strips. Task 1 extracts the complete exact key inventory into the default manifest and documents semantic keys in README before consumers change. Existing UI variables retain their names (without `--` in JSON); additional keys cover hardcoded control/text/gradient/alpha surfaces. Scene keys cover current PALETTE, STATUS, each distinct material ramp and fixed sky/FX/mail/fallback color. Use semantic keys, never literal-color lookup substitution. Duplicate colors may share a key only when they represent the same appearance role. Unknown keys fail validation against default inventory; strings accept only six-digit hex or numeric bounded `rgba(r,g,b,a)` (r/g/b integers 0–255, a 0–1), with no other CSS syntax. Ten project colors accept six-digit hex only. Default palette preserves current canvas stale label's blocked hue via a separate `stale` key; custom packs may distinguish it without changing stale behavior.

The following fixed brand capacities belong to the initial schema/default inventory, not a later redesign:

- `ui.typography` is `{profile, scale}`: `profile` is `classic` or `dm-sans`, `scale` is a finite number 0.9–1.1. Default is `classic`, 1. Application-owned profile tables map the existing chrome selectors to font metrics; no author font path, CSS shorthand or per-selector rules. Classic table preserves every current selector’s exact size/weight/line-height/tracking/case. DM Sans table uses body 14px/1.45, h1 500 20px/1 with .01em tracking/no uppercase, h2 600 24px/1.1, metadata 500 13px/1.3, buttons 500 13px/1.1 with zero tracking/no uppercase, tag/eyebrow 600 11px/1.6, project headings 600 14px/1.2; other chrome headings use the matching metadata/heading role. Apply scale only to these chrome sizes. Canvas text, `#page-label`, terminal totals and numeric stat values retain their existing fonts/metrics. Profile tables are fixed consumer rules; canonical default profile/scale and default colors/shapes remain in default JSON.
- `ui.shapes` has only `control`, `input`, `panel`, `sessionRow`, `mailRow`, `tag`, `eyebrow`, `badgeCut`. Each radius is four finite pixel numbers (top-left clockwise) in 0–24. Default copies current corners, including different session/mail rows; default tag/eyebrow radii are zero. `badgeCut` is `classic` or `none`, selecting existing chamfer clips or removing those clips. It never changes hit areas, padding, grid widths or canvas labels. Both packs may use rounded rectangles: controls/inputs 10–12px, panels 16–20px, rows/tags at bounded role-appropriate radii. No pill controls. Final values are content-review choices; B is not restricted to default chrome.
- `ui.decor` has only boolean `scanlines`, `glyphStrip`, `cornerBrackets`, `glow`, all true by default. Fixed selectors suppress their named decorative pseudo-elements/shadows, never focus outlines, status words, functional icons, stale cues or source-health indicators. C disables all four. These flags remain separate from the existing scene FX on/off control.
- `ui.logo` is null by default, otherwise `{image, alt}`. `image` is a pack-relative `branding/*.png` path under the same containment rules as crew; `alt` is a nonempty plain-text brand name ≤80 characters, assigned as an attribute. Slot sizing is application-owned (max-width 112px, height 24px, contain). Keep the existing decorative mark visible until local image decode succeeds; hide it only after success. Missing/undecodable image restores the mark and emits one bounded warning without hiding the “Local observer” heading or READ ONLY label. SVG is deliberately rasterized to transparent PNG at ≥2× slot dimensions: existing server MIME supports PNG/WOFF2 but not SVG. This avoids adding an SVG serving/sanitizing surface or parser dependency. Preserve source/logo provenance; do not inline source SVG or insert authored HTML.
- `scene.art` is `{style:"station"}` (default), or `{style:"home-office", assets:{...}}` with a complete fixed role-to-PNG map. Required roles are `floor`, `floorAlt`, `corridor`, `wallRearX`, `wallRearY`, `wallCorner`, `bookcaseX`, `bookcaseY`, `boardX`, `boardY`, `cabinetX`, `cabinetY`, `radiatorX`, `radiatorY`, `waterCooler`, `plant`, `basket`, `lamp`, `mailReception`, `mailPad`, `mailTray`, `dispatchCounter`, `mailSorter`, `desk`, `helperDesk`, `chair`, `helperChair`, `partitionX`, `partitionY`, `apron`, `planningBoard`, `planningShelf`, `viewer`, `carrier`. `frontend/app/scene-art-roles.js:SCENE_ART_ROLES` is the single application-owned metadata table. Role definitions specify source dimensions/foot anchor, render extent, tile repetition/orientation and existing depth pass; manifests author only contained `scene/*.png` paths. Task 1 defines the role table once for validator/render consumers, using current 48×24 projection and current reserved footprints/heights; bounded source dimensions are at most 512×512, floor/corridor tiles use 48×24 source diamonds. No authored atlas rectangles, offsets, scale, z/order, text, recipe language, layout or callbacks. Floor/walls/partitions repeat or clip their fixed role art within existing surfaces; props are authored to their fixed native render size without extra fractional per-prop fitting; no generic tileset/editor/import framework. Station path remains procedural and unchanged. Office artwork is original richly detailed pixel art, not palette-transformed station primitives. Each scene PNG is ≤256 KiB; total scene image bytes ≤6 MiB, ≤34 unique resources and ≤36 MiB decoded RGBA (34 maximum-size 512×512 roles use 34 MiB); complete selected crew/default fallback resources retain their separate budget. Combined decoded crew/scene image budget is ≤68 MiB, plus the existing independently bounded static cache. All resources use the same structural read, real-path containment, signature/IHDR and browser decode checks as crew/logo. `chair` is authored for root-worker and observatory chair bounds; `helperChair` is a distinct native-size PNG authored for the existing helper chair bounds under `worker.scale:0.72`. Draw each at its authored native size and existing chair anchor/depth pass, without scaling the root chair PNG down. Existing camera zoom remains unchanged; crew/helper scaling, chair presence and geometry remain unchanged.

- `scene.backgroundFx` is `rain` (default) or `none`; `scene.ambientFx` is `station` (default) or `none`. Rain selects the existing matrix layer. `none` skips it; ambient `none` disables space/starfield/nebula/planet/shuttle/pixies, decorative platform/furniture/desk/aura glows and sparks, retaining contact shadows, selection/focus/hover markers, status lamp/words and helper tethers. `home-office` requires both `none`; a mismatched explicit manifest is invalid. Home-office paints its flat warm semantic backdrop even with FX off. No gold-mote field or new particle system.


Bundle DM Sans locally inside each ignored pack selecting `dm-sans`, at its fixed `fonts/dm-sans.woff2` path with its matching `DM-Sans-OFL.txt`; verify the actual downloaded file’s family, supported weights (500/600), source and redistribution license before shipping.
