# Stale Refresh Implementation Plan

**Goal:** Reduce avoidable stale flicker by overlapping bounded identity captures and removing cache time added after enrichment.

**Architecture:** Keep refresh ownership in the backend. Resolve validated Herdr identities through four bounded workers, with a shared first-RPC admission gate and failure suppression inside the identity resolver. Preserve each pane's proof sequence, enrich transcripts/projects serially, then discover helpers; measure the two-second backend cache from refresh start while publishing actual per-source observation times.

**Tech stack:** Dependency-free CommonJS JavaScript, Node.js 22.13+, existing Python/libproc process-birth reader, Herdr read-only RPC, Node assertion tests, QuerySpine's existing test seams.

Reader: fresh implementers and reviewers. Implementation permission is pending. This draft authorizes no production edits, branches, commits, paid runs or live host observations. FX startup was fixed separately in commit `57d8c09`.

## Global constraints

- **Runtime:** Node.js 22.13+; native `node:sqlite` requires Node rather than substituting Bun. No npm package dependencies.
- **Privacy:** Loopback binding, per-launch API token, origin checks, bounded reads, identity checks, and redaction must remain intact. Presentation masking does not guarantee anonymity.
- **Truthfulness:** Missing sources remain unavailable and stale observations remain marked stale; unresolved identities must not open guessed transcripts.
- Keep six-second row/source freshness and two-second polling. Never use completion time as inventory time or widen the stale window.
- Preserve terminal incarnation, requested PID/process birth, semantic footer configuration and content-revision proof brackets. No proof, process-birth or terminal reuse across captures or refreshes.
- Preserve coalesced `get()` promises, authoritative empty/removal inventories, stable ordering, independent Desktop/Herdr health and timestamps, native Claude identities, footer withdrawal, socket teardown and bounded RPCs.
- Keep transcript/project reads serial and helper discovery after complete parent rows. Do not change transcript indices, helper bindings, inspector ownership checks or public snapshot shape.
- Limit production ownership to `sidecar/observer.js` and `sidecar/observer-identity.js`. No frontend runtime/theme edits, background services, public configuration or telemetry framework.
- Run tasks sequentially in the controller-created feature worktree after full approval and GSD registration. Preserve unrelated changes and agree concrete overlapping ownership before edits.
- Controller owns `.planning/drafts/stale-refresh/FLOW.json`; store review, approvals, cleanup evidence and progress there. Retain the approved plan verbatim in the registered GSD quick record through the controller's workflow.

### Task 1: Bound concurrent identity captures without weakening proof or outage suppression

**Goal:** Remove pane-by-pane identity serialization while preserving sampled identity proofs and existing initial-outage behavior.

**Execution:**

- Prerequisites: approved plan and registered feature worktree.
- Wave: 1.
- Mode: sequential-only; observer and identity tests form one coupled deliverable.
- Isolation: feature worktree; only the files below.
- Integration order: first; review its complete identity-to-row path before cache changes.

**Files:**

- Modify: `sidecar/observer-identity.js:makeIdentityResolver`, private `capture` and `processBirth` paths.
- Modify: `sidecar/observer.js:refreshHerdr`.
- Test: `test/observer-identity.test.js:fixture`, new `boundedIdentityRefresh` and `concurrentSuppression` cases.
- Test: `test/observer.test.js`, new `identityEnrichmentOrdering` case; retain existing `stalledFooterEndpoint` and identity/helper cases.

**Read first:**

- `sidecar/observer-identity.js:makeIdentityRpc`, `capture`, `resolve`, `processBirth`, `revalidateAll` — transport limits, proof sequence and suppression.
- `sidecar/observer.js:refreshHerdr`, `refresh`, `inspect` — publication and inspection race ownership.
- `sidecar/observer-transcripts.js:read`, `retain`, `resetHelperIndex`; `sidecar/observer-helpers.js:children`; `sidecar/observer-projects.js:resolve` — shared transcript indices, lineage mutation and ordered main-worktree proof cache.
- `test/observer-identity.test.js:sampledRaces`, `processBirthBoundary`; `test/observer.test.js:stalledFooterEndpoint`, `footerAncestryProofSet`, `helperComposition` — protected contracts.

**Current-state evidence:**

- `refreshHerdr` awaits each identity, transcript and project result before starting the next pane. It records `inventoryAt` before enrichment and assigns proofs/rows only after the loop succeeds.
- `capture` reads footer twice, terminal twice and process birth twice, and places the final conditional `pane.copy_motion` after every other awaited input. Independent pane captures share no proof object.
- `resolve` shares `endpointTimedOut` and `processBirthUnavailable` through refresh state, but checks them only before entering `capture`; admission alone cannot safely suppress subsequent operations in overlapping captures.
- `stalledFooterEndpoint` requires exactly one request against an initially silent socket and recovery next refresh. `sampledRaces` covers content, configuration, incarnation and PID reuse, with one final output probe.
- `children` resets shared transcript indices and mutates helper bindings. `resolve` in the project resolver depends on previously observed main roots. Neither path is authorized for parallelization.

**Intended edits:**

- Add `resolveMany(panes, refreshState)` inside `makeIdentityResolver`; use at most four capture workers, index results by input position and keep ordinary `resolve` behavior for direct callers.
- Give one refresh-scoped admission gate to the first actual capture RPC. It is the first pane's existing request, never an extra probe or evidence shared between panes. Other capture RPCs await its settlement before opening sockets. Publish `IDENTITY_TIMEOUT` suppression before releasing waiters; an initial timeout must cause exactly one RPC. A non-timeout failure remains capture-local, matching current retry behavior.
- After admission, permit bounded capture overlap. Check shared suppression immediately before each further RPC and process-birth read. Publish capability failure inside the read's catch before releasing other work. Outstanding reads may settle, but a suppressed capture returns unavailable and issues no further calls; do not fallback to old native identities. Use existing unavailable projection, retaining flags' current meanings.
- Pass refresh state through `capture` and `processBirth` only for roster resolution. `revalidateAll` continues its existing single-root sampled capture without adopting another refresh's gate or flags. Preserve each pane's existing call order and final conditional output probe; gate waits precede requests, never follow that last probe.
- Prevalidate supported pane IDs and duplicates in `refreshHerdr` before starting any identity workers. Call `identities.resolveMany` when available. Preserve existing injected `identities.resolve` adapters with a serial fallback, not unbounded `Promise.all`.
- Once identity results settle, build rows in inventory order using existing serial transcript/project reads. Publish rows, private proofs and retention together at the existing successful boundary. Keep helpers after both source refreshes.

**Interfaces:**

- Consumes: existing pane objects; refresh state with `endpointTimedOut` and optional `processBirthUnavailable`; existing injected RPC/process-birth/configuration seams.
- Produces: additional resolver method `resolveMany(panes, refreshState): Promise<Array<{sessionId, source, proof, reason}>>`, one result per pane in input order. Gate/worker bookkeeping is private and refresh-scoped. Existing exports, `resolve`, `retain`, `revalidate`, `revalidateAll` and browser data remain compatible.

**Dead-code scope:** Trace `resolve`, `capture`, `processBirth`, observer adapter injection and resolver exports with `rg`. Replace the obsolete serial identity loop, preserving serial fallback for supported injected adapters. Retain direct resolver/inspection APIs, process-birth reader and all security tests. Remove only confirmed orphaned helpers/imports introduced by this task; record uncertain consumers rather than deleting them.

**Review target:** Initial one-RPC outage, bounded sockets/process readers after admission, suppression publication races, per-pane proof sequence under interleaving, order/commit boundary, and serial downstream state. Reviewer uses `wnz-code-reviewer` with `INDEPENDENT_REVIEWER_LEAF` and `wnz-clean-code-js`; no further delegation.

### Task 2: Expire backend cache from refresh start and prove polling freshness

**Goal:** Ensure enrichment adds no new cache lifetime, and prove healthy/recovery timing through actual polling ownership.

**Execution:**

- Prerequisites: Task 1 approved and integrated.
- Wave: 2.
- Mode: sequential-only; shared observer/test files depend on Task 1.
- Isolation: same feature worktree; only files below.
- Integration order: second, followed by aggregate verification and independent branch review.

**Files:**

- Modify: `sidecar/observer.js:makeObserver`, `get`, `refresh`.
- Test: `test/observer.test.js`, new `refreshStartCache` and `pollingFreshness` cases.

**Read first:**

- `sidecar/observer.js:get`, `refresh`, `snapshot`, `aggregateRows` — cache timing differs from source/row freshness.
- `frontend/app/queryspine.js:ensureTimer`, `refresh`, `_setClockForTest`, `_setTimersForTest`, `_setGetForTest`, `_resetForTest` — existing fake polling seams.
- `frontend/app/observer.js:FRESH_MS`, `armDeadline`, observer.sessions definition — six-second deadline, two-second polling and 10000-ms request timeout.
- `test/queryspine.test.js` and `test/observer-ui.test.js` — existing scheduler and real stale presentation contracts.

**Current-state evidence:**

- `refresh` currently sets `refreshedAt = now()` after helper enrichment. `get` therefore adds two seconds after refresh completion to already aged inventory.
- `get` returns `pending` before examining cache age. `snapshot` copies independent source timestamps; Herdr rows retain the time inventory was read, while Desktop can supply its own timestamp.
- QuerySpine's poll callback calls `refresh` every configured interval. Its existing timer/get/clock injections permit testing that callback against `observer.get` without changing frontend runtime.
- Discovery measured serial identity cost as dominant, but occasional socket deadlines remain possible. No synthetic test proves all actual hosts stay fresh; outages and sustained slow reads must remain stale.

**Intended edits:**

- Replace completion-based `refreshedAt` with nullable private `refreshStartedAt`. Assign it exactly when `get` begins a new refresh. Cache only while `now() - refreshStartedAt < 2000`, checking `pending` first. Remove completion assignment from `refresh`; preserve timestamps and snapshot shape.
- Add fake-clock tests starting at zero, completing before and after two seconds. For a refresh starting at 0 and completing at 3000, the next `get` at 3000 begins another refresh; at 1999 reuse a short completed refresh, at 2000 refresh. Pending callers still receive the identical promise.
- Drive actual QuerySpine poll callbacks against actual backend observer/resolver using synthetic inventories, RPCs and deferred birth reads. Model 20 healthy panes, each with its existing nine RPCs totaling 250 logical milliseconds and two birth reads totaling 50 logical milliseconds; use 30 ms for each pane’s first footer read and distribute the remaining 220 ms across its eight remaining RPCs. Four workers complete five 300-ms waves, with first-admission wait accounted for, plus 100-ms serial downstream enrichment. Advance an injected logical clock and deferred events, not real delays. Assert each publication occurs within 1700 logical milliseconds of refresh start, inventory reads occur at 0, 2000, 4000 and 6000, and maximum age stays below 6000 for every healthy published row/source throughout pending intervals. These fixture durations are a behavioral model, not measured host performance.
- At a later poll hold identity or helper completion beyond a real six-second observation deadline. Assert old row/source `observedAt` values stay unchanged and age exceeds 6000 while pending; frontend stale contract remains covered by observer UI tests. Release or fail the work, assert unavailable retention versus authoritative removal, then allow recovery and verify actual new inventory timestamps.
- Include independently older Desktop timestamps to prove fresh Herdr does not refresh Desktop age. Unsubscribe and reset QuerySpine fixtures in `finally`; existing request timeout timers must clear when deferred requests settle.

**Interfaces:**

- Consumes: `options.now`, existing `get(): Promise<snapshot>`, existing resolver/observer injections and QuerySpine test seams.
- Produces: same public observer API; private cache age now derives from refresh start. No new clock, route, configuration or frontend seam.

**Dead-code scope:** Trace and remove all `refreshedAt` completion-cache references in `sidecar/observer.js`. Preserve source timestamps, aggregate freshness checks and UI deadlines. Trace test fixture registrations and restore QuerySpine seams; remove only obsolete cache expectations, preserving source freshness and pending-coalescing assertions.

**Review target:** Zero-clock sentinel, exact cache boundary, slow completion, no overlap of pending refreshes, real scheduler callback path, truthful delayed observations and independent sources. Reviewer uses `wnz-code-reviewer`, `INDEPENDENT_REVIEWER_LEAF` and `wnz-clean-code-js`.
